# 筑安智巡 · SiteSafe-Sentinel 1.2.0

这一版以可理解、可操作、可恢复的桌面工作体验为目标，不再把压缩包体积作为优先约束。保留全部原有案例与嘉然素材，不改模型检测策略，不增加 MLLM 调用。

## 打开软件

完整解压交付文件夹，双击根目录 `SiteSafe-Sentinel.exe`。不要只移动 EXE。软件需要 Windows 10/11 64 位与 WebView2，演示运行使用随包 Python 和已构建的前端，不要求系统 Node、GPU 或模型权重。

首次登录可用示例账号：管理员 `admin / admin123`、安全员 `safety / safety123`、总监 `viewer / viewer123`。真实账号权限由业务后台决定。正式部署应修改默认账号，按项目分配权限。

首次进入工作台会显示快速开始引导，可选择“先看作品”“接入真实检测”或“日常巡检”，也可以直接跳过。引导不会自动启动模型或修改配置；个人操作清单不等于系统验收结果。

## 不知道功能在哪里？

- 右上角“搜索功能”，或 `Ctrl + K`：搜索“模型”“导入规范”“检测桥”“备份”等关键词，进入具体模块或页签。按 Enter 打开首项，Esc 关闭。
- “本页指南”：说明当前模块的操作步骤、得到的结果、注意事项与下一步。
- 左侧“使用与支持”：快速开始、功能全景、连接诊断与常见问题。
- 搜索和引导按账号权限过滤；需要管理员的操作不会作为普通账号可用入口出现。

## 三条使用路径

### 查看作品

使用与支持 → 快速开始 → 先看作品 → 检测结果汇总 → 风险工单。

八个案例的原图、报告、掩码和展示资产保留。若之前隐藏了预置素材，引导页会提示显式重新启用。启用只影响显示，不把演示案例写入真实事件数据库。“展示视图”控制外观，“预置展示素材”控制数据展示，两者不同。

### 接入真实检测

系统设置 → 桌面与连接 → 选择完整 Python 环境 → 模型规则配置 / 模型部件与运行时 → 选择权重与推理引擎 → 校验保存 → 启动 Qwen → 图片检测 → 检查证据。

SAM3、YOLO、可选 CLIP 按任务加载，不必因为没有立刻占用显存而反复启用。检测桥在线不等于模型在线；配置通过不等于推理验收通过。云端模式需要明确选择并配置服务，不假定其一定比本地结果更好。

真实检测连接失败时保留用户选择，明确阻止提交，不会偷偷退回 Mock。演示模式单独标记，不能当作现场安全结论。

### 日常巡检与闭环

视频监控 → 检测任务中心 → 风险证据 → 人工复核 / 工单 → 案例与复盘。

离开页面不会取消后台任务。排队任务可以取消，运行中任务不提供强杀。关闭整个桌面窗口会停止其启动的服务。RTSP 检测输入与窗口预览地址可分别配置；窗口不直接播放 RTSP。

## 界面与交互改进

专业工作台使用墨青导航、暖色强调、统一卡片、字体层次与留白，增加建筑线稿视觉元素；嘉然动画与作品展示视图保留。明暗主题共用语义颜色。窗口顶部提供当前项目、功能搜索、页面指南与连接诊断；用户操作收拢至头像菜单。

新增键盘焦点、跳转到正文、可键盘选择示例图、减少动态效果适配、无数据时的行动入口。图片输入支持 JPG/PNG/WebP，单张不超过 20 MB；无效文件明确提示。释放旧预览内存，避免反复选图积累对象 URL。

## 故障提示与恢复

连接诊断统一检查业务后台、检测桥、本地与云端配置，显示“待检查”“未连接”“配置齐备”和“服务就绪”的区别。各状态带对应处理入口。页面共享 15 秒只读检查，不为每个诊断面板重复轮询。

可导出状态摘要给维护人员，摘要只包含检查时间、服务状态和排队数量，不含密钥、图片、路径、接口地址或用户信息。桌面窗口中可打开日志文件夹；完整日志另行分享前需检查敏感信息。

启动失败页提供完整解压、Python 依赖和端口冲突的处理步骤，可打开固定的软件目录或日志目录，不允许任意路径或命令执行。

## 本轮修复的链路细节

- 搜索直达知识库、模型运行时、桌面环境等页签；链接、后退和页签选择保持一致。
- 修复从任务中心进入既有任务时初次没有加载详情的问题。
- 修复连接刷新把真实检测模式改成演示的问题。
- 修复已缓存项目名称与项目列表不一致；旧请求不会覆盖新项目数据。
- 工作台加载失败保留上次内容并提供重试，不静默显示成功。
- 离开工作台移除图表窗口监听，避免反复导航累积监听器。
- 连接设置保存前校验地址，拒绝磁盘路径、密钥式参数及带账号密码的 URL；恢复默认尊重部署预设。
- 桌面接口延迟初始化时仍可加载配置，不误判为普通浏览器。

## 交付与后续开发

本版同时保留完整的前端 `public/` 资源与 `dist/` 构建产物，便于继续修改设计；不再为了体积要求先恢复公共素材。模型权重仍外置，便于不同硬件选择。详细依赖见 `requirements/`。业务库备份并非完整系统备份，完整迁移还需保留输出图片、知识库、运行配置和业务附件。

验证记录见文档目录中的 `v1.2验收记录.md`。本轮是产品体验与软件链路优化，不是模型精度评测、商业认证或长期生产负载验收。代码签名、自动更新服务器、组织级部署策略和真实多摄像头长期验证仍需要独立的后续工作。
