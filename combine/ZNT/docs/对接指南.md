# 对接指南
---

## 一、说明

| 层级 | 目录 | 职责 | 对接时是否改页面 |
|------|------|------|------------------|
| 接口层 | `*/api/` | HTTP 请求、入参出参 | 否（优先只改这里） |
| AI 层 | `*/ai/` | 视觉大模型 / 推理 / 处置智能体 | 否 |
| 模拟数据 | `*/mock/` | 本地假数据 | 对接完成后可删除 |
| 请求工具 | `utils/request.js` | baseURL、Token | 改配置 |
| 页面 | `views/` / `pages/` | UI 与交互 | 一般不改 |

**口诀：先改 api 与 ai，再改环境变量，最后才动页面。**


**打开方式**

1. 双击根目录 **`start-platform.bat`**（自动开两个服务并打开浏览器）  
2. 或先双击 `start-platform.bat`，等窗口出现 `Local: http://localhost:5173/` 后再点 `.url`

## 注：用 example 测试图做「上传→检测→结论」

1. 用上面方式打开平台并登录  
2. 左侧菜单进入 **「实时检测」**  
3. 在「线下图片上传」下方，点击 **测试图片（来自仓库 example/）** 七张之一  
4. 点 **开始检测**  
5. 右侧会逐步展示：接收图像 → 视觉初检 → 分割掩码 → 证据核验 → 二次确认 → 风险推理 → 处置建议  
6. 完成后查看结论、标注图，可跳转工单处置  

说明：

- 若未启动检测桥接：页面自动走**本地演示流程**（阶段动画 + 与所选测试图对应的结论）  
- 若已启动 `start-platform.bat（已内置）`：图片会真正提交到 `detect_bridge.py`（默认 Mock 算法，无需 GPU）  
- 原始图仍在仓库 `example/`；网页用的是同步副本 `pc-admin/public/examples/`

## 二、Mock/后端

### PC 管理端

1. 打开 `pc-admin/src/utils/request.js`  
2. 将 `USE_MOCK` 改为 `false`  
3. 复制 `pc-admin/.env.example` 为 `.env.local`，填写：

```env
VITE_API_BASE=https://你的后端域名/api
VITE_VISION_API=https://你的AI网关/vision/detect
VITE_REASON_API=https://你的AI网关/reason/analyze
VITE_ACTION_API=https://你的AI网关/action/create-order
```

4. 如需本地代理，打开 `pc-admin/vite.config.js` 中的 `server.proxy` 注释并填写。

### 大屏

大屏现已默认读取业务后台 `GET /api/screen/overview`。可用 `?api=http://服务器:8800` 临时切换地址，或设置构建变量 `VITE_API_BASE`；仅在 `VITE_USE_MOCK=true` 时启用独立演示数据。

### 移动端

移动端现已默认连接业务后台与检测桥：业务地址可用 `?api=http://服务器:8800` 指定，检测桥可用 `?detect=http://服务器:8810` 指定；也可使用 `VITE_API_BASE`、`VITE_DETECT_API` 构建变量。H5 会使用安全员演示账号获取会话，正式部署应替换为移动端登录页或企业单点登录。

1. `USE_MOCK = false`  
2. 修改 `BASE_URL`  
3. 各函数已写好 `uniRequest`，可直接走真实接口。

## 三、AI 模型对接

PC 端入口：`pc-admin/src/ai/`  
移动端入口：`mobile/ai/index.js`

### 0. 推荐：实时检测整链路桥接（图片/摄像头 → 平台结果）

当前已接通内置YOLO实时初筛：上传/摄像头帧先生成`ScreeningTrigger`和粗区域，再按门控策略进入VLM、SAM3及Agent。也支持在请求中传入外部实时模型生成的`screening_json`。完整协议、字段和门控说明见[《YOLO-VLM-前端接口整合说明》](./YOLO-VLM-前端接口整合说明.md)。

这是「线下图片端到平台检测结果」的主路径，已直接接入 `detectmodel/Site_Safety_OpenRisk` 算法包。

| 项 | 说明 |
|----|------|
| 桥接服务 | `detectmodel/Site_Safety_OpenRisk/detect_bridge.py` |
| 启动 | 根目录 `start-platform.bat`（可选 Mock / 云端 / 本地） |
| 前端页 | 菜单「实时检测」`/realtime-detect` |
| 前端 API | `pc-admin/src/api/detect.js` |
| Vite 代理 | `/detect-api` → `http://127.0.0.1:8810` |

流程：上传图片或摄像头截帧 → 桥接调用检测流水线 → 阶段状态回传 → 生成叠加图/事件契约 → 前端展示。

模式对应配置：

```bash
cd detectmodel/Site_Safety_OpenRisk
# 1 演示 Mock
python detect_bridge.py --config configs/default.yaml --port 8810
# 2 云端视觉（Qwen API + 本地 SAM3/CLIP）
python detect_bridge.py --config configs/qwen_visual.yaml --port 8810
# 3 本地权重（本地 Qwen + 本地 SAM3/CLIP）
python detect_bridge.py --config configs/qwen_local_zero_cost.yaml --port 8810
```

RTSP 连续抽帧仍用 `run_stream_inspection.py`，事件可通过 `app_server.py` 的 `/api/ingest/event` 推入；浏览器侧截帧走桥接 `POST /api/detect/camera-frame`。

### 1. 视觉大模型（Vision）

- 文件：`pc-admin/src/ai/vision.js`  
- 函数：`receiveRiskDetection(payload)`  
- 对接内容：目标检测 / 分割结果  
- 坐标约定：最终统一为**画面百分比 0～100**（可用 `maskRender.js` 的 `toPercentMask` 转换）

**建议调用时机：**

- 后端通过 WebSocket 推送检测结果 → 前端调用 `receiveRiskDetection` 规范化  
- 或前端定时截帧上传（带宽较大，优先后端推送）

### 2. 推理智能体（Reason）

- 文件：`pc-admin/src/ai/reason.js`  
- 函数：`analyzeRisk(payload)`  
- 对接内容：风险定级、规范条文、处置建议、是否需要建单

### 3. 处置智能体（Action）

- 文件：`pc-admin/src/ai/action.js`  
- 函数：`autoCreateWorkOrder(payload)`  
- 编排函数：`runAiPipeline(payload)`（视觉→推理→工单一条龙）  
- 演示入口：首页底部按钮「演示 AI 检测链路」

### 掩码渲染

- 文件：`pc-admin/src/ai/maskRender.js`  
- 组件：`pc-admin/src/components/RiskMask`  
- 视频叠加：`VideoPlayer` 已内置掩码层，传入 `masks` 即可。

## 八、新增功能规范

新增一个业务页面时，请按下列顺序：

1. **mock**：在 `src/mock/index.js` 增加模拟数据（开发阶段）  
2. **api**：在 `src/api/xxx.js` 新建接口函数，写清 JSDoc 入参/出参，内部 `USE_MOCK` 分支  
3. **view**：在 `src/views/模块名/index.vue` 写页面，只调用 api，不直接 import mock  
4. **router**：在 `router/index.js` 注册路由，并配置 `meta.title / icon / roles`  
5. **组件复用**：视频、掩码、工单卡片优先用 `components/` 下公共组件  
6. **注释**：文件头说明模块作用 +「后续修改入口」  

移动端同理：`mock → api → pages → pages.json`。
