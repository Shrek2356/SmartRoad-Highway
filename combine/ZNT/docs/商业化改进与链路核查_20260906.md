## 3. 已复现的功能问题

### F01：桌面静态服务缺少业务 API 转发（最高优先级）

证据位置：`desktop/desktop_app.py:99`、`pc-admin/src/utils/endpoints.js:4`、`pc-admin/vite.config.js:23`。

前端默认访问 `/business-api/api` 和 `/detect-api`。开发期 Vite 有相应代理，桌面 `SpaHandler` 仅提供静态文件与 SPA 路由回退，没有这些代理，也没有 POST 处理。

对真实 `SpaHandler` 在临时本地端口的复现结果：

| 请求 | 实际响应 | 影响 |
|---|---|---|
| GET `/business-api/api/health` | 200，`text/html`，内容为前端 index.html | 健康检查可能误判 |
| GET `/detect-api/api/detect/health` | 200，`text/html`，内容为前端 index.html | 检测桥未被正确访问 |
| POST `/business-api/api/auth/login` | 501 | 默认配置下真实登录无法完成 |

修复建议：建立统一的桌面网关，转发 HTTP 方法、上传、媒体和 WebSocket；或者由启动器向前端注入真实端点并同步所有媒体、推送地址。优先选同源网关，以减少地址配置与跨域状态不一致。API 未知路径必须返回 API 错误，不能返回 HTML。

验收：从交付目录用全新用户状态启动，完成真实登录、列表加载、一次隔离测试检测任务、结果图片展示和业务通知推送。不得只测后台独立端口。

### F02：新增用户无法按实际账号登录（高优先级）

证据位置：`pc-admin/src/api/auth.js:29`。

已复现：调用实际登录函数，输入用户名 `new_site_manager`、角色 `safety`，发往服务器的用户名变成 `safety`。代码按角色覆盖用户输入，还包含预设密码替换逻辑。

修复建议：正常登录原样提交用户名和密码；快捷演示账号单独作为显式入口。真实角色由后端认证结果确定。

验收：管理员创建一个自定义安全员账号，该账号可登录并只获得对应权限；预设演示账号仍能通过演示入口体验。

### F03：同名规范更新失败会丢失原规范（高优先级）

证据位置：`detectmodel/Site_Safety_OpenRisk/detect_bridge.py:1039`。

已在临时知识库中复现：先上传有效 `safety-rule.txt` 返回 200，再上传同名仅包含空白的文件返回 422，原文件也被删除。原因是先覆盖旧文件，解析失败后直接删除目标。

修复建议：先写临时文件、解析与校验成功后原子替换；失败保持旧文件与旧索引。增加修订版本和回滚记录。

验收：同名有效替换更新检索结果；无效替换、解析异常和中断均不影响旧版本继续检索。

### F04：桌面退出会向非本次启动的桥发送停止 Qwen 请求（高优先级）

证据位置：`desktop/desktop_app.py:268`。

隔离 mock 复现：桌面实例拥有 0 个子进程，调用 stop 仍会向 8810 的 `/api/detect/qwen-service/stop` 发起请求。这可能干扰由其他入口启动、但被其检测桥管理的 Qwen。

修复建议：记录服务及模型进程的启动归属；只停止本实例拥有的进程。共享服务只断开连接。启动中关闭应通过取消标记和锁阻止后续继续拉起服务。

验收：复用已有服务后关闭窗口，已有服务保持运行；由本实例启动的服务正常退出；启动过程中关闭不残留进程。

### F05：重启后“最近任务”遗漏已完成历史（高优先级）

证据位置：`detectmodel/Site_Safety_OpenRisk/detect_bridge.py:356`、`:392`。

隔离复现：磁盘中存在 `done` 任务，按 ID 读取成功，但执行重启恢复逻辑后 recent 列表数量为 0。恢复逻辑只装载 queued/running，recent 只查询内存。

修复建议：任务列表使用持久化索引，完成、失败、取消与进行中的任务统一分页查询；内存仅用于运行状态加速。

验收：完成任务后重启，仍可按项目、时间、状态查到结果及证据；任务日志、业务事件和预置案例不要互相代替。

## 5. 前端商业化设计方向

### 5.1 品牌与演示素材

产品主名称统一为“筑安智巡”，英文技术名称保留 SiteSafe-Sentinel；嘉然动画和形象保留在启动页、关于页和展示模式。专业工作台缩小顶部装饰区域，让主要空间用于风险、证据和操作。

保留已有八张案例、检测框、掩码、预编辑点位和展示统计。把展示素材显示设为可切换的运行时选项，并显式标记数据来源。现在相关开关主要在构建时生效，不方便交付后切换。

展示风格和数据来源是两个独立设置：用户可以采用专业配色展示案例，也可以在保留形象元素的界面查看真实数据。不能靠“真实数据条目较少”判断它无效；统计值为零也可以是真实业务状态。

### 5.2 按用户任务组织导航

建议围绕以下区域组织现有功能，而不是继续平铺更多模型或 Agent 名称：

- 工作台：待处理风险、超时工单、在线设备、今日趋势及快捷操作。
- 实时巡检：视频源、采集状态、检测任务、定时全图检查。
- 风险处置：检测结果、人工复核、工单流转、证据对照。
- 知识与复盘：行业规范、历史案例、统计分析、学习建议与交底。
- 系统设置：模型与环境、用户、通知渠道、数据备份、软件版本与诊断。

将“用户与备份”从 Agent 学习中心迁至系统设置；Agent 的技术贡献通过事件处理时间线、规范引用和处置结果展示，业务操作使用安全员熟悉的名称。

### 5.3 重点完善三个交互区域

1. 全局运行状态：当前项目与模式、服务连接状态、活动任务数和最后更新时间；支持打开诊断详情。
2. 统一风险详情：左侧原图/框/掩码对照和缩放，右侧模型判断、可见证据、不确定性、规范来源和人工操作；底部展示完整处理记录。
3. 任务中心：排队/运行/完成/失败/取消状态，真实阶段耗时、任务来源与时间、重试和结果入口；切换页面或重启后能够恢复。

界面基础统一字号、间距、按钮高度、图标与风险颜色。沿用已有主题变量，逐步替换页面硬编码和大范围 CSS 强制覆盖。验收覆盖 1366×768、1920×1080、125%/150% DPI、明暗主题、弹窗、空状态及错误状态。

## 6. 后端长期运行与技术贡献

### 调度效率

保留当前有界单 GPU 队列与检测器缓存。在多摄像头场景增加每设备保留最新帧、近似重复帧合并、过期任务淘汰、按风险与到期时间调度。衡量从采集到通知的端到端延迟，而不只看模型计算时间。30/120 分钟全面检查应记录成功完成时间及失败状态，并在失败后安排补偿检查。

### 模型接口与证据

沿用可替换 MLLM、SAM3、CLIP 和 YOLO 适配器。每个结果记录模型版本、推理配置、提示词版本、风险目录版本、原图标识和各阶段耗时。升级模型后重跑八张关键示例及冻结的异常/控制集，用效果、误报与耗时共同决策。

### Agent 与规范库

规范库增加解析预览、条款与页码定位、版本替换和回滚。当前知识库实际使用字符 TF-IDF 路径，开头说明提到的优先 sentence-transformers 不应作为已经实现的能力宣传。扫描 PDF 的 OCR 可以作为可选能力，先准确提示“未解析出正文”。

复盘学习保留人工审批。下一步为阈值/规则提案增加在固定样本集上的影响预览，以及回滚版本，避免只根据被复核样本里的驳回比例直接推断整体误报率或盲目提高阈值。

这些工作突出可复现的系统贡献：持续感知调度、稳定工具契约、可追溯证据、人机复核、规范更新和可控的闭环改进，不需要把贡献全部归结为更大的 MLLM。
